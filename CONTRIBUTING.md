# Contributing to QTEP

Thank you for your interest in improving the Quantum Tool Evaluation Protocol (QTEP).

QTEP is intended to evolve through practical application, reproducible evidence, constructive criticism, and community feedback.

Contributions are welcome from quantum developers, researchers, maintainers, educators, tool users, and others with relevant experience.

## Ways to Contribute

Useful contributions may include:

* reporting ambiguity in the protocol;
* identifying evaluation criteria that produce misleading results;
* suggesting improvements to existing methodology;
* proposing category-specific evaluation criteria;
* identifying reproducibility problems;
* improving documentation;
* suggesting improvements to evaluation templates;
* reproducing published evaluations;
* providing evidence that challenges a QTEP conclusion;
* correcting factual or technical errors.

Not every contribution needs to include code.

## Before Proposing a Protocol Change

Please consider:

1. **What problem does the proposed change solve?**
2. **Was the problem observed during an actual evaluation or reproduction attempt?**
3. **Could the issue be resolved through clarification rather than additional methodology?**
4. **Would the change improve evaluations across a class of tools, or only affect one particular result?**
5. **Could the proposed change introduce unintended bias or complexity?**

QTEP favors the minimum methodology necessary to reach defensible conclusions.

## Issues

Opening an issue is generally the best way to propose a significant methodological change.

A useful issue should describe:

* the relevant QTEP version;
* the observed problem or ambiguity;
* how the issue affects an evaluation;
* supporting evidence or an example where available;
* the proposed change, if one is known.

Discussion may reveal that no protocol change is necessary.

That is a valid outcome.

## Pull Requests

Pull requests are welcome for:

* documentation improvements;
* corrections;
* template improvements;
* agreed methodological changes;
* other changes discussed through repository issues.

For significant changes to the protocol itself, opening an issue before submitting a pull request is encouraged.

Pull requests should explain:

* what is changing;
* why the change is needed;
* what evidence or experience supports the change;
* whether the change affects existing QTEP evaluations.

Acceptance of a pull request into the canonical repository remains at the discretion of the QTEP maintainers.

## Evidence Over Preference

QTEP welcomes disagreement.

When possible, methodological proposals should be supported by:

* evaluation results;
* reproduction attempts;
* counterexamples;
* technical reasoning;
* documented user workflows;
* other relevant evidence.

The objective is not consensus for its own sake. The objective is a methodology that produces fair, useful, and reproducible evaluations.

## Tool Maintainers

Maintainers of tools evaluated using QTEP are particularly welcome to:

* identify factual errors;
* clarify intended behavior;
* point to relevant documentation;
* reproduce evaluation results;
* provide counterexamples;
* identify invalid assumptions.

Maintainers do not control evaluation verdicts, but technically supported corrections and challenges should be taken seriously.

## Scope of Contributions

QTEP is an evaluation methodology.

Contributing to QTEP does not create an obligation for QTEP maintainers to:

* repair evaluated software;
* maintain third-party projects;
* provide technical support for evaluated tools;
* perform requested evaluations;
* adopt every proposed tool category or metric.

## Licensing of Contributions

By contributing to the QTEP methodology or documentation, contributors agree that their contributions may be distributed under the same license applicable to the QTEP materials they modify.

Please do not contribute material that you do not have the right to share under the applicable license.

## Conduct

Constructive technical disagreement is welcome.

Discussion should focus on:

* claims;
* evidence;
* methodology;
* reproducibility;
* technical reasoning.

Personal attacks, harassment, or attempts to manipulate evaluation outcomes are not appropriate contributions to the project.

---

**Contribution principle:**

> Find a real methodological problem, bring evidence when possible, propose the minimum sufficient improvement, and let practical experience drive the protocol.
